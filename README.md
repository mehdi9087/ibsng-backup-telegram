# بکاپ خودکار IBSng به تلگرام

نصب تک‌دستوریِ سرویس بکاپ دیتابیس IBSng داخل Docker، با دریافت تنظیمات هنگام نصب.
این پروژه خود IBSng یا Docker را نصب نمی‌کند و برای IBSng نصب‌شده مستقیم روی سیستم طراحی نشده است.

## نصب آسان

روی سرور دارای IBSng با دسترسی root اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/mehdi9087/ibsng-backup-telegram/main/install.sh -o /tmp/ibsng-backup-install.sh && sudo bash /tmp/ibsng-backup-install.sh
```

اگر با root وارد شده‌اید و `sudo` نصب نیست، `sudo` را از فرمان حذف کنید.
نصاب کانتینر و دیتابیس را با بررسی کانتینرهای فعال و جدول‌های IBSng به‌صورت خودکار پیدا می‌کند؛ نام‌های سفارشی هم پشتیبانی می‌شوند. اگر فقط یک گزینه پیدا شود، این دو سؤال نمایش داده نمی‌شوند. در صورت وجود چند گزینه، فهرست انتخاب نشان داده می‌شود؛ اگر تشخیص ممکن نباشد، ورود دستی درخواست می‌شود. تنظیمات ذخیره‌شدهٔ نصب قبلی حفظ می‌شوند.

سپس نام یا IP نمایشی سرور، مسیر ذخیره، فاصلهٔ بکاپ به ساعت، مدت نگهداری محلی، فعال‌بودن ارسال تلگرام، توکن ربات، آیدی عددی مقصد و ارسال بدون اعلان پرسیده می‌شوند. توکن هنگام تایپ نمایش داده نمی‌شود. متن‌های اسکریپت انگلیسی‌اند و راهنما فارسی است.

پیش از نصب، ربات را در تلگرام Start کنید. برای گروه، ربات باید عضو گروه و مجاز به ارسال فایل باشد؛ برای کانال باید اجازهٔ انتشار داشته باشد. آیدی گروه/کانال معمولاً منفی است.

پیش‌فرض زمان‌بندی: بکاپ ساعتی و نگهداری محلی ۷۲ ساعت. کانتینر و دیتابیس به‌صورت خودکار شناسایی می‌شوند. مقدار صفر برای نگهداری یعنی حذف نشدن فایل‌های قدیمی.

نصب اولیه یک بکاپ واقعی می‌گیرد و به مقصد تعیین‌شده می‌فرستد؛ تنها پس از موفقیت، تایمر فعال می‌شود. اگر مقصد یا ارتباط تلگرام مشکل داشته باشد، نصب خطا می‌دهد و فایل‌های نصب قبلی را بازمی‌گرداند. بکاپ ساخته‌شده باقی می‌ماند.

## پیش‌نیاز و دامنهٔ بکاپ

- Linux با systemd، Bash 4.3 یا جدیدتر، Docker فعال و IBSng از قبل نصب‌شده.
- دسترسی کاربر `postgres` در کانتینر به `pg_dump` و `psql` و دیتابیس IBSng.
- ارتباط HTTPS با Telegram API؛ روی سرورهای دارای محدودیت شبکه، ارتباط لازم است.
- نصاب در صورت نیاز curl، CA certificates، gzip، util-linux و Python 3 را با apt/dnf/yum نصب می‌کند.

خروجی یک dump کامل SQL از **دیتابیس انتخاب‌شده** است؛ فایل‌های برنامه، تنظیمات سیستم، volume کامل Docker و نقش‌های سراسری PostgreSQL را شامل نمی‌شود. رمز دیتابیس/توکن/بکاپ واقعی در این مخزن وجود ندارد.

## امکانات

- فایل `sql.gz` با دسترسی `600`، بررسی سلامت gzip و ثبت SHA256 و آمار users/ras/admins در فایل `.meta`.
- ارسال فایل و مشخصات آن به تلگرام؛ تأیید هر دو وضعیت HTTP و `ok: true`.
- جلوگیری از اجرای هم‌زمان با flock؛ در خطای دیتابیس فایل ناقص منتشر نمی‌شود.
- حذف بکاپ‌های قدیمی همان دیتابیس و نام سرور، فقط پس از اجرای موفق. فایل‌های نامرتبط حذف نمی‌شوند.
- حفظ تنظیمات و زمان‌بندی قبلی هنگام اجرای دوبارهٔ نصب‌کننده؛ ذخیرهٔ نسخهٔ قبلی زیر `/var/backups/ibsng-backup-installer-*`.
- بکاپ ساعتی با `OnCalendar=hourly` و جبران اجرای ازدست‌رفته پس از روشن‌شدن سرور؛ فاصله‌های دیگر با تایمر systemd و شروع اولیه پنج دقیقه پس از بوت.

فایل بزرگ‌تر از ظرفیت ارسال Telegram API به قطعات تقسیم نمی‌شود؛ در صورت رد ارسال، فایل محلی حفظ می‌شود و سرویس خطا گزارش می‌کند. بازگردانی واقعی روی دیتابیس جداگانه را متناسب با نسخهٔ PostgreSQL خود آزمایش کنید.

## مدیریت

```bash
# وضعیت زمان‌بندی
systemctl status ibsng-backup-telegram.timer

# بکاپ و ارسال فوری
systemctl start ibsng-backup-telegram.service

# گزارش آخرین اجراها
journalctl -u ibsng-backup-telegram.service -n 50 --no-pager

# توقف بکاپ خودکار (بدون حذف بکاپ‌ها یا تنظیمات)
systemctl disable --now ibsng-backup-telegram.timer

# فعال‌سازی مجدد
systemctl enable --now ibsng-backup-telegram.timer
```

تنظیمات: `/etc/ibsng-backup-telegram.env` با دسترسی root و `600`.
محل پیش‌فرض بکاپ‌ها: `/opt/ibsng/backups/telegram`.
برای تغییر نام کانتینر، مقصد یا فاصلهٔ بکاپ، فایل نصاب را دوباره دریافت و اجرا کنید:

```bash
sudo bash /tmp/ibsng-backup-install.sh --reconfigure
```

برای تغییر دستی کانتینر یا دیتابیس، گزینه‌های `--container NAME --database NAME` را به فرمان نصب اضافه کنید. تشخیص خودکار فقط ساختار جدول‌ها را بررسی می‌کند و نام دیتابیس به‌تنهایی ملاک نیست. دسترسی کاربر `postgres` به فهرست دیتابیس‌ها و جدول‌های `public.users`، `public.ras` و `public.admins` لازم است؛ اگر دسترسی محدود باشد، مشخصات را دستی بدهید.

گزینه‌ها:

| گزینه | رفتار |
| --- | --- |
| `--check` | بررسی فقط‌خواندنی Docker و دیتابیس با تنظیمات موجود؛ بدون نصب یا ارسال |
| `--detect` | تشخیص فقط‌خواندنی کانتینر و دیتابیس؛ بدون نصب یا بکاپ |
| `--container NAME` | انتخاب دستی کانتینر؛ در صورت ندادن دیتابیس، دیتابیس آن دوباره شناسایی می‌شود |
| `--database NAME` | انتخاب دستی دیتابیس |
| `--skip-test` | فعال‌سازی بدون بکاپ اولیه؛ سلامت ارسال در این حالت تأیید نمی‌شود |
| `--non-interactive` | استفاده از تنظیمات موجود یا متغیرهای محیطی؛ بدون پرسش |
| `--reconfigure` | دریافت دوبارهٔ تنظیمات و ساخت زمان‌بندی جدید |
| `--extract DIR` | استخراج اسکریپت بکاپ برای بررسی؛ بدون نصب |

فایل تنظیمات از نوع Bash است و باید فقط توسط root قابل ویرایش باشد. برای نصب خودکار، مقادیر نمونهٔ `config.example.env` را از مسیر امن به متغیرهای محیطی بدهید؛ اطلاعات واقعی را در Git ثبت نکنید.

## آزمون‌ها

```bash
bash -n install.sh
bash -n backup.sh
python3 test_installer.py
```

تست‌ها روی Linux با Docker، systemd و Telegram شبیه‌سازی‌شده در مسیر موقت اجرا می‌شوند؛ تست‌ها چیزی به تلگرام ارسال نمی‌کنند. شامل dump ناقص، خطای شبکه، پاسخ HTTP ناموفق، `ok:false`، JSON خراب، نگهداری فایل‌ها، نصب اولیه، حفظ تنظیمات و بازگردانی نصب قبلی هستند.

اعتبارسنجی عملی: بکاپ محلی روی Ubuntu 24.04 با PostgreSQL 8.4.20 داخل کانتینر IBSng آزمایش شده است. ارسال واقعی تلگرام در نسخهٔ جدید و بازگردانی کامل دیتابیس در این بررسی اجرا نشده‌اند؛ تست ارسال هنگام نصب انجام می‌شود.
